# 로그인 페이지 요구사항

## 로그인: 기본

- [x] 이메일 주소와 비밀번호 입력창 유무 확인
  - [x] 이메일 주소 입력창: 입력값 표시 확인
  - [x] 비밀번호 입력창: 입력값 마스킹(⚫️) 처리 확인
- [x] 로그인 API 연동 (POST /api/auth/login)
  - [x] Request Body: { email, password }
- [x] '회원가입' 링크 클릭 시 회원가입 페이지 이동

## 로그인: 유효성 검증

### 이메일 유효성

- [x] 공백 불가
- [x] 이메일 주소 형식 준수 (예: example@naver.com)

### 비밀번호 유효성

- [x] 공백 불가
- [x] 8자 이상
- [x] 영문 + 숫자 조합

### 유효성 검증 동작

- [x] 초기 상태: 입력창 기본 스타일 유지
- [x] 유효성 실패 시 시각적 피드백
  - [x] 입력창 테두리 빨간색 변경
  - [x] 에러 메시지 표시
    - 아이디: "이메일 형식으로 작성해 주세요."
    - 비밀번호: "비밀번호는 8자 이상, 영문과 숫자 조합이어야 합니다."
- [x] 로그인 버튼 상태 제어
  - [x] 유효성 검사 통과 전: 버튼 비활성화 (로그인 시도 불가)
  - [x] 유효성 검사 통과 후: 버튼 활성화

## 로그인: 실패/성공

- [x] 로그인 실패 처리
  - [x] 알림 메시지: "로그인 정보를 다시 확인해 주세요"
  - [x] 알림 종료 후 이메일 입력창으로 포커스 이동
- [x] 로그인 성공 처리
  - [x] 응답 객체 `isFirstLogin` 확인
    - `true`: 프로필 설정 페이지로 이동
    - `false`: 타이머 페이지로 이동
  - [x] 뒤로가기 제어: 로그인 페이지 재진입 불가

## 로그인: 인증-인가 정책

- [ ] JWT 기반 인증 구현
- [ ] 토큰 발급 및 관리
  - [ ] Access Token: 유효시간 1시간
  - [ ] Refresh Token: 유효시간 10일 (240시간)
- [ ] 토큰 갱신 (Access Token 만료 시)
  - [ ] POST /api/auth/refresh 호출
- [ ] 로그아웃 (Refresh Token 만료 시)
  - [ ] 로그인 페이지로 리다이렉트

## 로그인: 중복 로그인 처리

- [x] 중복 로그인 감지 (응답 객체 `isDuplicateLogin`)
  - [x] `true` (중복 로그인 상황):
    - [x] 안내 메시지 표시: "중복 로그인된 다른 기기의 로그인이 풀립니다."
    - [] 확인 후 로그인 진행
  - [x] `false` (일반 로그인):
    - [x] 타이머 페이지로 이동
- [ ] (서버 측) 기존 기기 강제 로그아웃 및 타이머 기록 삭제 확인
